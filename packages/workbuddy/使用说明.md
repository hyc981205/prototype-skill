# WorkBuddy 包 — 使用说明

四个符合 WorkBuddy 技能规范的技能，可直接本地安装，也可上传技能市场。

```
WorkBuddy包/
├── 使用说明.md
├── skills/
│   ├── prototype-design-interview/   需求访谈 → DESIGN_SPEC + PROMPT
│   ├── prototype-workflow/           新建/修改原型流程 + 工作区模板
│   ├── frontend-design/              高保真 UI 初稿
│   └── ui-ux-pro-max/                设计数据库（Python 检索）
└── 上传市场/                          四个 zip，SKILL.md 均在包根
```

---

## 一、本地安装（推荐先这样试）

### 用户级（所有项目可用）

PowerShell：

```powershell
$dst = "$env:USERPROFILE\.workbuddy\skills"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item -Recurse -Force ".\skills\*" $dst
```

Git Bash：

```bash
mkdir -p ~/.workbuddy/skills
cp -r skills/* ~/.workbuddy/skills/
```

### 项目级（随项目走，团队共享）

```powershell
$dst = "D:\你的项目\.workbuddy\skills"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item -Recurse -Force ".\skills\*" $dst
```

复制后在 WorkBuddy 设置页的「技能」中应能看到四个技能。看不到就重启应用或重新扫描。

### 准备原型工作区

`prototype-workflow` 需要项目的 `prototypes/` 工作区：

```powershell
New-Item -ItemType Directory -Force -Path "D:\你的项目\prototypes" | Out-Null
Copy-Item -Recurse -Force ".\skills\prototype-workflow\assets\workspace\*" "D:\你的项目\prototypes\"
```

复制后 `prototypes/` 内应有：`skills/01–06`、`_template/`、`README.md`。

## 二、环境要求

- WorkBuddy PC 端（技能功能已开放）
- Python 3.8+（仅 `ui-ux-pro-max` 检索脚本需要）
- Git（版本发布用，可选）

验证设计检索：

```bash
python ~/.workbuddy/skills/ui-ux-pro-max/scripts/search.py "admin dashboard" --design-system
```

Windows 若 `python3` 不可用，改用 `python`。

## 三、怎么用

### 说不清要做什么

> 我想做个原型但没想清楚：我们组每周手工排资源占用表，十几个人好几个项目，改一个人要
> 群里挨个问。你引导我问，想清楚后给我 DESIGN_SPEC.md 和 PROMPT.md，先别写代码。

触发 `prototype-design-interview`。

### 需求清楚，新建原型

> 新建一个原型「备件领用」：列表字段 料号/名称/规格/库存/领用人/日期/状态，
> 支持搜索和状态筛选，纯 HTML/CSS/JS。

触发 `prototype-workflow` 的 A 流程。

### 改已有原型

> 给「备件领用」加一个状态筛选下拉框。

触发 `prototype-workflow` 的 B 流程。应看到：先复述架构 → 追加需求记录 → 改代码 →
更新架构文档。

### 视觉优化

> 把这个原型的视觉做专业一点，配色和字体给个方案。

触发 `ui-ux-pro-max`；需要高保真初稿时再触发 `frontend-design`。

## 四、上传技能市场（可选）

`上传市场/` 下已按「SKILL.md 在 zip 根目录」打包好：

| 文件 | 上传入口 |
|---|---|
| `prototype-design-interview.zip` | 技能 |
| `prototype-workflow.zip` | 技能 |
| `frontend-design.zip` | 技能 |
| `ui-ux-pro-max.zip` | 技能 |

流程：开放平台 → 专家·技能·连接器 → 技能 → 技能市场 → 添加技能 → 创建技能 → 上传 zip。
市场展示还需要 512×512 PNG 头像（≤500KB），本包未附带，上传时自行准备。
审核通常约 7 个工作日；更新时递增 `version` 字段。

## 五、验收

| 阶段 | 看什么 |
|---|---|
| 访谈 | 第一问是「现在怎么做」；布局题给具体选项；问过「哪些这次不做」；两份文件结构完整 |
| 新建 | 原型目录六件套齐全；双击 index.html 可开；README 索引更新 |
| 修改 | 先读并复述架构；先追加需求记录再改代码；改完同步架构文档 |
| 设计 | 配色/字体有明确选择；空/加载/错误状态存在；无水平滚动 |

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 技能列表里没有 | 复制位置不对 | 确认 `~/.workbuddy/skills/<name>/SKILL.md` 层级正确 |
| 技能不触发 | description 未命中 | 首条消息带触发词：「新建原型」「你问我答」 |
| 检索脚本报错 | 未装 Python 或路径不对 | 用绝对路径试跑；或只读 SKILL.md |
| 工作区缺失 | 没复制 assets/workspace | 按「准备原型工作区」补 |
| 市场解析失败 | zip 里 SKILL.md 在子目录 | 用 `上传市场/` 里已打好的 zip |

## 七、与 Claude 版的差异

- 技能名不带命名空间（Claude 插件版是 `ui-ux-pro-max:ui-ux-pro-max`）
- `prototype-workflow` 把工作区模板放在技能自己的 `assets/workspace/`，首次使用需复制到项目
- 设计 skill 的数据库检索需要手动跑 Python；不跑也能用 SKILL.md 里的规则
