# 技术规范（开发阶段）

原型一律是纯静态文件，浏览器双击即可运行。本文件是开发阶段的硬约束。

---

## 一、目录与文件

每个原型一个目录，中文命名，扁平存放：

```
prototypes/<原型名>/
├── index.html              页面骨架
├── style.css               样式（CSS 变量主题）
├── script.js               交互逻辑
├── NOTES.md                创建日期 / 目的 / 场景 / 数据说明
├── REQUIREMENTS.md         需求审计链（只追加，不删）
└── CODE_ARCHITECTURE.md    代码架构索引（修改前必读）
```

- 原型目录不嵌套子目录；需要图片/图标时放 `assets/`
- 不建 `package.json`、不引入构建工具
- 每个原型有独立 Git 版本线（如 `备件领用/v1.0`），用 tag 代替备份目录

---

## 二、HTML 规范

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>工具名</title>
  <link rel="stylesheet" href="style.css">
  <!-- 外部库 CSS 在此，位于 style.css 之前 -->
</head>
<body>
  <div id="app">
    <!-- 页面结构 -->
  </div>
  <!-- 外部库 JS 在此，位于 script.js 之前 -->
  <script src="script.js"></script>
</body>
</html>
```

必须：
- `lang="zh-CN"`、`viewport`、`charset="UTF-8"`
- 语义标签 `<header> <main> <nav> <section> <footer>`
- 表单用 `<form>` + `<label for>`，按钮用 `<button>`，禁止 `<div onclick>`

三种常见布局：

**控制面板型**
```
header.toolbar
main.workspace
  aside.panel-left      280px 固定
  section.panel-main    自适应
footer.statusbar
```

**仪表盘型**
```
header.toolbar
main.dashboard    卡片网格
```

**单页表单型**
```
main.form-container
  section.input-area
  section.action-bar
  section.output-area
```

## 三、CSS 规范

### Reset（必须）

```css
*, *::before, *::after { margin: 0; padding: 0; box-sizing: border-box; }
```

### 主题变量（必须，所有颜色走变量）

```css
:root {
  --color-primary: #4F46E5;
  --color-primary-hover: #4338CA;
  --color-primary-light: #EEF2FF;

  --color-bg: #F9FAFB;
  --color-surface: #FFFFFF;
  --color-border: #E5E7EB;
  --color-text: #111827;
  --color-text-secondary: #6B7280;

  --color-success: #059669;
  --color-warning: #D97706;
  --color-error: #DC2626;

  --spacing-xs: 4px;  --spacing-sm: 8px;  --spacing-md: 16px;
  --spacing-lg: 24px; --spacing-xl: 32px;

  --text-sm: 12px;  --text-base: 14px; --text-lg: 16px;
  --text-xl: 20px;  --text-2xl: 24px;

  --radius-sm: 4px; --radius-md: 8px; --radius-lg: 12px;
  --shadow-sm: 0 1px 2px rgba(0,0,0,.05);
  --shadow-md: 0 4px 6px rgba(0,0,0,.07);
  --shadow-lg: 0 10px 15px rgba(0,0,0,.1);
}
```

```css
body {
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
               "Microsoft YaHei", sans-serif;
  font-size: var(--text-base);
  color: var(--color-text);
  background: var(--color-bg);
  line-height: 1.6;
  min-height: 100vh;
}
```

规则：
- 主布局 Flexbox，复杂网格 Grid；禁 `float`
- 禁 `!important`（覆盖第三方库除外）
- 三栏：`flex: 0 0 280px` + `flex: 1`
- 断点：768px（平板）、480px（手机）；侧栏小屏折叠
- 组件类统一：`.btn` `.btn-primary` `.btn-secondary` `.btn-danger`
  `.form-input` `.form-select` `.form-label` `.form-error`
  `.card` `.state-loading` `.state-empty` `.state-error`

## 四、JS 规范

```js
(function () {
  'use strict';

  // ── 状态 ─────────
  // ── DOM 引用 ─────
  // ── 事件绑定 ─────
  // ── 工具函数 ─────
  // ── 初始化 ───────
})();
```

- 查询缓存 `document.querySelector()`；事件用委托 + `closest()`
- 禁止 `innerHTML` 拼接用户可见内容，用 `textContent` / `createElement`
- 搜索输入 300ms 防抖；表单监听 `submit`；错误就近显示在 `.form-error`
- 状态管理：变量 + `render()` 重渲染；复杂原型可用简易观察者
- 禁 Redux / Vuex / Pinia
- 导出文件用 `Blob` + `URL.createObjectURL` + `<a download>`，不引第三方库

数据：

```js
const MOCK_DATA = {
  list: [
    { id: 1, name: '示例一', status: 'active' },
    { id: 2, name: '示例二', status: 'inactive' }
  ],
  total: 42
};
```

- 列表 5–15 条，足够演示筛选/分页
- 结构对齐真实接口，便于后续对接
- 用 `setTimeout` 模拟 300–800ms 延迟，展示 loading

## 五、外部库

默认不用。仅当「做得逼真」或「接近上线效果」时才引，且只走白名单：

| 场景 | 库 | CDN（锁版本） |
|---|---|---|
| 响应式框架 | Vue 3 | `unpkg.com/vue@3.4.0/dist/vue.global.prod.js` |
| UI 组件 | Element Plus | `unpkg.com/element-plus@2.5.0/dist/index.full.min.js` + CSS |
| 图表 | ECharts 5 | `cdn.jsdelivr.net/npm/echarts@5.4.3/dist/echarts.min.js` |
| 图标 | Lucide | `unpkg.com/lucide@0.300.0/dist/umd/lucide.js` |
| 日期 | dayjs | `cdn.jsdelivr.net/npm/dayjs@1.11.10/dayjs.min.js` |
| 工具函数 | Lodash | `cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js` |

禁：jQuery、Bootstrap、React、Angular、任何需要构建的库。
引入顺序：库 CSS 先于 `style.css`；库 JS 先于 `script.js`。

判断：纯 HTML/CSS 能做 → 自己做；少量交互（tab/弹窗）→ 自己做；
要图表 → ECharts；要完整组件（日期选择/下拉树）→ Element Plus；其他先问用户。

## 六、流程

### 新建

1. 确认名称（中文目录名）与范围
2. 复制 `原型模板/` 的四个文件到 `prototypes/<名称>/`
3. 写 `NOTES.md`
4. 写 `REQUIREMENTS.md`（若已有 `DESIGN_SPEC.md`，转写其要点）
5. 先给布局方案 + 模拟数据结构，用户确认后再编码
6. 编码
7. 写 `CODE_ARCHITECTURE.md`：文件索引、HTML 骨架、CSS 类、JS 函数/状态/事件
8. 在索引表登记

### 修改（六步，禁止跳过）

1. **读** `CODE_ARCHITECTURE.md`，用一句话向用户复述当前架构
2. **读** `REQUIREMENTS.md`
3. **追加**变更记录：`### YYYY-MM-DD — [新增/修改/删除/修复] 标题` + 内容 + 原因
4. **编码**：只动需要改的部分
5. **同步**架构文档：函数、状态变量、数据模型、事件、HTML 骨架、CSS 类
6. **提交**：`原型名 vX.Y: 摘要`，tag `原型名/vX.Y`

版本：功能新增 +0.1；重构/破坏性改动 +1.0；修 bug 递增小版本。
每次提交只对应一个原型。

## 七、交付自检

- [ ] 双击 `index.html` 可直接打开，控制台无报错
- [ ] 所有颜色来自 `:root` 变量
- [ ] 主流程可只用键盘完成
- [ ] 至少实现空数据与无结果两种状态
- [ ] 无 `float`、无 `!important` 滥用、无 `innerHTML` 拼用户内容
- [ ] `CODE_ARCHITECTURE.md` 与代码一致
- [ ] 需求变更都有记录
