# 豆包工作包 — 使用说明

## 这个包是什么

给豆包工作（或其他「知识库 + 系统提示词」型 agent）用的一套前端原型协作规则。
不需要安装 skill，上传文件 + 粘贴提示词即可。

```
豆包工作包/
├── 使用说明.md              本文件
├── 系统提示词.md            粘贴到自定义指令
├── 知识库/
│   ├── 01-完整规则.md       主规则（可单独使用）
│   ├── 02-问题库.md         提问措辞 + 6 种布局草图 + 8 种工具形态
│   ├── 03-输出模板.md       DESIGN_SPEC / PROMPT 模板
│   ├── 04-技术规范.md       HTML/CSS/JS、外部库、新建与修改流程
│   └── 05-设计准则.md       视觉优先级、四套配色、组件状态、反模式
└── 原型模板/
    ├── index.html
    ├── style.css
    ├── script.js
    ├── CODE_ARCHITECTURE.md
    └── 说明.md
```

## 安装（5 分钟）

1. 打开豆包工作 → 知识库 / 文件管理
2. 上传 `知识库/` 下 **5 个文件**
   （容量有限时至少要传 `01-完整规则.md`；其余按需）
3. 打开 `系统提示词.md`，复制两条横线之间的内容
4. 粘贴到「系统提示词 / 自定义指令 / 人设与回复风格」
5. 新建对话，发开场语

## 怎么用

### 说不清要做什么

> 参照知识库里的规则，开始给我做需求访谈。

然后按它的提问回答。它会：一轮问一个宏观问题 → 给布局草图选项 → 每轮回声确认 →
输出 `DESIGN_SPEC.md` 和 `PROMPT.md` 的完整内容。

### 需求已经清楚

> 参照知识库里的规则，按下面需求新建原型：备件领用。主区列表字段：料号、名称、规格、
> 库存、领用人、领用日期、状态；支持搜索和状态筛选。

它会给出布局与数据结构，然后输出三个文件内容。

### 改已有原型

> 参照知识库里的规则，给「备件领用」加一个状态筛选下拉框。先告诉我当前架构，再改。

## 拿到产出后怎么落地

豆包不能直接写你电脑上的文件，需要你手动落盘：

1. 在本地建目录 `prototypes/<原型名>/`
2. 复制 `原型模板/` 里的四个文件进去
3. 把豆包输出的 `index.html`、`style.css`、`script.js` 内容分别覆盖进去
4. 把 `DESIGN_SPEC.md`、`PROMPT.md`、`REQUIREMENTS.md`、`CODE_ARCHITECTURE.md`
   按它给的内容存成文件
5. 双击 `index.html` 验收

## 限制

| 限制 | 影响 | 替代做法 |
|---|---|---|
| 不能读写本地文件 | 产出要手动复制 | 让它按「一个文件一块代码」的格式输出 |
| 不能执行命令 | 无法跑设计数据库、Git | 设计走 `05-设计准则.md`；版本命令手动执行 |
| 上下文有限 | 长对话后半段可能忘规则 | 每轮结束提醒「继续按知识库规则」；长任务拆成访谈、开发两段对话 |
| 知识库检索不稳定 | 可能只读部分文件 | 首条消息明确「先读 01-完整规则」 |

## 验收标准

- 访谈阶段：第一问是「现在怎么做」，不是「你想要什么功能」
- 布局题给了具体选项，不是开放问句
- 问过「哪些这次不做」
- 两份产出文件结构完整，`PROMPT.md` 能单独粘到新会话成立
- 开发阶段：三个文件齐全，双击可开，控制台无报错
