# 豆包工作包 — 使用说明

## 这个包是什么

给**豆包工作（桌面客户端）**用的一套前端原型 Skill。装进用户技能目录即可，不需要每轮粘贴
提示词，也不需要上传知识库。

```
豆包工作包/
├── 使用说明.md                 本文件
└── skills/
    ├── prototype-design-interview/   需求模糊时的结构化访谈，产出 DESIGN_SPEC.md + PROMPT.md
    ├── prototype-workflow/           新建/修改原型的强制流程（六件套文档 + 架构同步 + Git tag）
    ├── frontend-design/              高保真 UI 初稿，避开通用「AI 味」设计
    └── ui-ux-pro-max/                可检索设计数据库（50+ 风格 / 161 配色 / 57 字体配对 / 99 UX 准则）
```

四个是一组，**不要只装一部分**：访谈技能产出规格后交给 workflow，workflow 在写样式时会调用
frontend-design 与 ui-ux-pro-max。

## 安装

### 方式一：一条命令

```powershell
Copy-Item -Recurse -Force "packages/doubao/skills/*" `
  "$env:LOCALAPPDATA\DoubaoWork\User Data\Default\.doubaowork\agent_mode\workspace\.user_skills"
```

### 方式二：手动复制

技能目录默认在：

```
C:\Users\<用户名>\AppData\Local\DoubaoWork\User Data\Default\.doubaowork\agent_mode\workspace\.user_skills
```

把 `skills/` 下 4 个文件夹整个复制进去，与已有技能目录平级。不确定路径时，让豆包自己报：
「把我当前使用的技能目录（.user_skills）的完整路径发我」。

### 装完

重启客户端（或新开一个会话），技能列表才会刷新。发一句验证：

> 用 prototype-workflow 新建一个原型

它先问原型名、目的、数据规模，就说明装好了。

## 环境要求

- 豆包工作桌面客户端（Windows）
- Python 3.8+（仅 `ui-ux-pro-max` 的检索脚本需要）。没有 Python 也不影响前三个技能，
  只是设计检索改为直接读 `SKILL.md` 里的规则表。

## 怎么用

### 说不清要做什么

> 我想做个原型但没想清楚：我们组每周手工排资源占用表，十几个人好几个项目，改一个人要群里
> 挨个问。你引导我问，想清楚后给我一套提示词。

走 `prototype-design-interview`：一轮问一个宏观问题 → 给具体布局选项 → 每轮回声确认 →
最后问「哪些这次不做」→ 输出两张文件，移交给 `prototype-workflow`。

### 需求已经清楚

> 新建一个原型「备件领用」：主区列表字段 料号/名称/规格/库存/领用人/日期/状态，
> 支持搜索和状态筛选，纯 HTML/CSS/JS。

走 `prototype-workflow` Workflow A：确认范围 → 读规范 → 建目录 → 布局与数据确认 → 编码 →
`CODE_ARCHITECTURE.md` → 更新索引 → 提交。

### 改已有原型

> 给「备件领用」加一个状态筛选下拉框。

正常表现：读架构文档并一句话复述 → 读需求记录 → 追加变更 → 编码 → 提交前同步架构文档。

### 发版本 / 设计优化

> 发布 v1.1
> 调用 ui-ux-pro-max 审查「备件领用」的配色和间距

## 首次使用会自动建工作区

`prototype-workflow` 第一次被触发时，若项目里没有 `prototypes/`，会先建好目录、
`CLAUDE.md`、`README.md` 索引和 `_template/` 空白模板（都打包在技能的 `assets/` 里），再开工。
每个原型一个目录，六件套：`index.html` / `style.css` / `script.js` / `NOTES.md` /
`REQUIREMENTS.md` / `CODE_ARCHITECTURE.md`，双击 `index.html` 即可验收。

## 与 `packages/claude-code` 的区别

技能内容同源，本包做了三处适配，否则在豆包工作里跑不通：

| 项目 | Claude Code 包 | 本包 |
|---|---|---|
| 工作区规范位置 | 项目内 `prototypes/CLAUDE.md` + `prototypes/skills/01–06` | 打包进 `prototype-workflow/references/`，模板进 `assets/` |
| 技能间调用 | `Skill` 工具 + `skill:"X"` | 读取对方 `SKILL.md` 并按其中内容执行 |
| 设计检索命令 | `python3 skills/ui-ux-pro-max/scripts/search.py` | `python "<本 SKILL.md 所在目录>/scripts/search.py"` |
| 技能描述 | YAML 折叠式 `description: >` | 单行引号串，保证技能列表解析后能触发 |

原 Claude Code 包不做改动，两套并存。

## 注意事项

- **文件夹名不要改**：技能名即目录名，`SKILL.md` 里的 `name` 必须一致
- **不要嵌套**：`skills/<技能名>/SKILL.md`，不能变成 `.user_skills/豆包工作包/skills/<技能名>/`
- 对方已装过同名技能（尤其 `ui-ux-pro-max`）时，先备份再覆盖，避免丢自己的改动

## 验收

- 技能列表里能看到 4 个名称
- 说「新建原型」时，先问范围而不是直接写代码
- 改已有原型时，先复述架构再动手
- 产出的原型双击可开、控制台无报错
