## 一、布局草图（Round 2 第 4 题）

用 `AskUserQuestion` 的 `preview` 字段并排展示，用户指认远比描述容易。
先按整图形状选，主区形态选中后仍可替换 —— 说一句"主区那块的形态后面还能换"。

### 1. 控制面板型 — 筛选/配置类
```
┌──────────────────────────────────┐
│ 工具栏          标题      [操作] │
├────────┬─────────────────────────┤
│ 筛选   │                         │
│ 条件   │      主区               │
│ 分组   │   （表格/列表/图）      │
│        │                         │
└────────┴─────────────────────────┘
```
侧栏常驻，改动筛选条件主区实时响应。

### 2. 列表管理型 — 台账/CRUD
```
┌──────────────────────────────────┐
│ 工具栏   [搜索]   [+ 新增]       │
├──────────────────────────────────┤
│ 列头 │ 列头 │ 列头 │  操作       │
│ ─────┼──────┼──────┼──────────   │
│      │      │      │ 编辑 删除   │
│      │      │      │             │
├──────────────────────────────────┤
│ 共 N 条          ‹ 1 2 3 ›       │
└──────────────────────────────────┘
        ↑ 增删改走弹窗/抽屉
```
最常见的一种。适合"有很多条记录要管"。

### 3. 主从详情型 — 浏览 + 查细节
```
┌──────────────────────────────────┐
│ 工具栏   [搜索]                  │
├─────────────┬────────────────────┤
│ 列表        │  详情              │
│ ○ 条目一    │  字段：值          │
│ ● 条目二    │  字段：值          │
│ ○ 条目三    │  ──────────        │
│             │  关联内容列表      │
└─────────────┴────────────────────┘
```
左边点，右边看。适合"选中一条要看它的一堆细节"。

### 4. 仪表盘型 — 状态总览
```
┌──────────────────────────────────┐
│ 工具栏   标题      时间范围      │
├──────────────────────────────────┤
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐     │
│ │指标│ │指标│ │指标│ │指标│     │
│ └────┘ └────┘ └────┘ └────┘     │
│ ┌──────────────┐ ┌─────────────┐ │
│ │   趋势图     │ │  分布图     │ │
│ └──────────────┘ └─────────────┘ │
└──────────────────────────────────┘
```
适合"只看状态，不编辑数据"。

### 5. 单页表单型 — 输入 → 产出
```
┌──────────────────────────────────┐
│ 标题                             │
├──────────────────────────────────┤
│ 输入区                           │
│  字段 [____]  字段 [____]        │
│  字段 [____]                     │
├──────────────────────────────────┤
│           [ 生成 ]  [ 清空 ]     │
├──────────────────────────────────┤
│ 输出区（结果/预览/导出）         │
└──────────────────────────────────┘
```
一次填完出结果，没有列表。适合计算器、生成器、配置器。

### 6. 看板型 — 状态流转
```
┌──────────────────────────────────┐
│ 工具栏   [搜索]  [+ 新建]        │
├────────┬────────┬────────┬───────┤
│ 待处理 │ 进行中 │ 待确认 │ 已完成│
│ ┌────┐ │ ┌────┐ │ ┌────┐ │       │
│ │卡片│ │ │卡片│ │ │卡片│ │       │
│ └────┘ │ └────┘ │ └────┘ │       │
│ ┌────┐ │        │        │       │
│ │卡片│ │        │        │       │
└────────┴────────┴────────┴───────┘
```
东西少、状态重要、要拖来拖去时用。

## 二、主区形态（布局选定后，可替换用）

- **表格** — 多列对齐、可排序筛选。信息密度最高。
- **卡片列表** — 每条一张卡，字段少但视觉重。适合"每条内容长短不一"。
- **树 / 层级表** — 有父子层级时。
- **看板列** — 按状态分列。
- **日历 / 时间轴** — 时间维度是主维度时。
- **表单** — 本身就是一次输入。

问法："主区那一块，你希望是**一行行的表格**，还是**一张张卡片**？"
别问"主区形态是什么" —— 用户没有这个词。

## 三、业务对象（Round 2 第 2 题）

**不要问**："你的领域模型是什么？""有哪些实体？"

**要问**："举个具体例子说说。比如：我一个项目下面有 5 个任务，每个任务派给一个人 —— 你那边是什么样的？"

拿到例子后自己拆：
- 名词 → 实体（项目、任务、人）
- 数字 → 基数（1 对 N）
- 动词 → 关系（"派给" = 分配）

然后回声确认："所以是 项目 → 任务 → 人 三层，一个项目多个任务，一个任务一个人，对吗？"
用户改这句比写这句省力得多。

## 四、主区内容定义（Round 3 第 1 题）

**不要问**："需要哪些列？" 空白用户会卡住。

按顺序试这几句，哪句用户答得上就用哪句：

1. **"把你现在那个 Excel 的表头念给我。"** —— 最有效，直接白拿字段。
2. **"你希望在一条记录里一眼看到哪几个信息？"**
3. **"你上次做这件事时，眼睛在找哪几个数？"**
4. **"如果只能留 3 列，你留哪 3 列？"** —— 逼出主次。

拿到字段后补：
- 每个字段的类型（文本/数字/日期/枚举/关联）
- 枚举型字段的取值范围（状态有哪些？类型有哪些？）
- 哪些字段要能搜、能筛、能排序

## 五、状态与交互分支（Round 3 第 2 题）

**默认全给，让用户删。** 用户想不出需要什么，但能快速否掉不需要的。

清单：

| 分组 | 项 |
|---|---|
| 状态 | 空数据空态 / 加载中 / 出错 / 搜索无结果 |
| 增删改 | 新增 / 编辑 / 删除 + 二次确认 / 行内编辑 |
| 批量 | 批量选择 / 批量操作 / 全选 |
| 长列表 | 分页 / 滚动加载 |
| 出入 | 导入（粘贴·上传）/ 导出（Excel·CSV） |
| 呈现 | 弹窗 / 抽屉 / 页内展开 |
| 流转 | 状态流转（待办→进行中→完成）/ 审批（提交→通过·驳回） |
| 其他 | 角色区分 / 撤销 / 键盘操作 |

问法："这几个我先都放进去，你看看哪些是多余的 —— 用不上的删掉。"
不要问"你需要哪些状态"。

## 六、视觉基调（Round 3 第 3 题）

给 2–3 个，配类比。用户认得出风格，说不出风格名。

| 基调 | 描述 | 类比 |
|---|---|---|
| 专业冷色 | 蓝灰主色、白底、信息密集、边框清晰 | 内部管理后台 |
| 工业深色 | 深底、等宽数字、高对比色 | 监控大屏、工控界面 |
| 轻量明亮 | 大留白、圆角、柔和色、阴影轻 | 现代 SaaS 产品 |
| 高对比企业风 | 强色块、严谨表格式、线框明确 | 报表系统 |

若用户没有偏好，`prototypes/AGENTS.md` 的默认 CSS 变量体系已经是「专业冷色」，直接沿用，
省一次决策。

## 七、常见工具形态（空白用户的救命路径）

用户全程"我不知道"时，不要硬问。从下表挑 2–3 个最接近的当骨架，让用户选一个，再在骨架上改。

| 形态 | 一句话 | 典型布局 |
|---|---|---|
| 台账管理 | 一堆记录要增删改查 | 列表管理型 |
| 配置器 / 向导 | 多步选择，最后产出一份配置 | 单页表单型 |
| 比对 / 校验 | 两边数据放一起看差异，逐条处理 | 主从详情型 |
| 盘点 / 巡检 | 一份清单逐项打勾、记状态 | 列表管理型 |
| 排期 / 分配 | 资源 × 时间或位置，做分配 | 控制面板型 |
| 监控看板 | 多个指标卡片 + 趋势，只看不改 | 仪表盘型 |
| 录入 + 导出 | 填表单，生成文件带走 | 单页表单型 |
| 审批流 | 提交 → 审核 → 状态变化 | 主从详情型 |

问法："听起来最接近哪一个？先按它搭，之后改起来很快。"

## 八、通用兜底

用户答不出任何一题时，回到同一条路：**给他一个具体的东西，让他改。**

- 不要重问。重问一个答不出的问题只会消耗耐心。
- 给默认值 + 一句理由 + "后面随时能改"。
- 把这条记进 `DESIGN_SPEC.md` 的「待确认项 / 已用默认值」节，让用户事后能回头改。
