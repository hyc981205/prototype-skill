# Codex 包 — 使用说明

## 这个包是什么

一个可直接作为项目根目录使用的 Codex 工作区。包含：

- `AGENTS.md` — Codex 自动读取，负责访谈流程与硬约束
- `references/` — 访谈问题库、输出模板、设计兜底
- `.codex/skills/` — 两个设计 skill（frontend-design、ui-ux-pro-max）
- `prototypes/` — 原型工作区（规则、6 个技术规范、空白模板）

## 安装（二选一）

### A. 这一包就是项目根

```bash
cd <解压目录>\Codex包
codex
```

直接在包目录里启动即可。新建的原型会出现在 `prototypes/` 下。

### B. 复制进已有项目

```bash
cd D:\你的项目
cp -r <解压目录>\Codex包\AGENTS.md    .
cp -r <解压目录>\Codex包\references   .
cp -r <解压目录>\Codex包\.codex       .
cp -r <解压目录>\Codex包\prototypes   .
```

若项目已有 `AGENTS.md` 或 `prototypes/`，先合并内容，不要直接覆盖。

## 环境要求

- Codex CLI / IDE 扩展
- Python 3.8+（仅 `ui-ux-pro-max` 检索脚本需要；没有也能用，只是少了数据库检索）

验证：

```bash
python .codex/skills/ui-ux-pro-max/scripts/search.py "admin dashboard" --design-system
```

## 怎么开始

### 情况 1：说不清要做什么

> 按 AGENTS.md 的流程来。我想做个原型但没想清楚：我们组每周手工排资源占用表，十几个人
> 好几个项目，改一个人要群里挨个问。先问我问题，别写代码；想清楚后给我 DESIGN_SPEC.md
> 和 PROMPT.md。

Codex 会：一次问一个宏观问题 → 给多套布局草图选项 → 每轮回声确认 → 写两份文件。

### 情况 2：需求已经清楚

> 按 AGENTS.md 和 prototypes/AGENTS.md，新建原型「备件领用」。主区列表字段：料号、名称、
> 规格、库存、领用人、领用日期、状态；支持搜索和状态筛选；纯 HTML/CSS/JS。

Codex 会：读规范 → 复制模板 → 先给布局与数据结构等确认 → 编码 → 写架构文档 → 更新索引。

### 情况 3：改已有原型

> 给「备件领用」加一个按状态筛选的下拉框。按六步流程走。

必须看到它：先读 `CODE_ARCHITECTURE.md` 并复述 → 读 `REQUIREMENTS.md` → 追加变更记录 →
改代码 → 更新架构文档。

## 验收

```bash
ls prototypes/备件领用/
# index.html  style.css  script.js  NOTES.md  REQUIREMENTS.md  CODE_ARCHITECTURE.md
start prototypes/备件领用/index.html
```

浏览器直接打开、控制台无报错，即达标。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| Codex 没按流程问 | AGENTS.md 不在项目根 | 确认根目录有 `AGENTS.md` |
| 说找不到问题库 | `references/` 没复制 | 补复制到根目录 |
| 设计检索报错 | 没装 Python 或路径不对 | 用包内绝对路径试跑；或改读 SKILL.md |
| 原型被建到别处 | 工作区路径不明 | 明确说「建在 prototypes/ 下」 |

## 限制

- 无 Git 仓库时不提交；Codex 会输出命令清单，由你执行
- 设计 skill 的 1.6MB 数据库依赖 Python；纯靠 `SKILL.md` 也能工作，但配色/字体细节会弱一些
- 不要一次抛多个需求，访谈会被跳过
