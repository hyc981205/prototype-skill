# ClaudeCode 包 — 使用说明

## 这个包是什么

一个可直接用 Claude Code 打开的原型工作区。项目级技能已就位，无需安装到用户目录。

```
ClaudeCode包/
├── CLAUDE.md                  ← 启动时自动读
├── .claude/skills/            ← 四个技能（项目级，随目录生效）
│   ├── prototype-design-interview/
│   ├── prototype-workflow/
│   ├── frontend-design/
│   └── ui-ux-pro-max/
└── prototypes/
    ├── CLAUDE.md              ← 工作区规则（强制）
    ├── README.md              ← 原型索引
    ├── skills/01–06
    └── _template/
```

## 安装（二选一）

### A. 这一包就是项目根

```bash
cd <解压目录>\ClaudeCode包
claude
```

### B. 复制进已有项目

```bash
cd D:\你的项目
cp -r <解压目录>\ClaudeCode包\.claude     .
cp -r <解压目录>\ClaudeCode包\prototypes  .
cp <解压目录>\ClaudeCode包\CLAUDE.md      .
```

若项目已有 `.claude/` 或 `CLAUDE.md`，先合并，不要直接覆盖。

## 环境要求

- Claude Code
- Python 3.8+（仅 `ui-ux-pro-max` 检索脚本需要）
- Git（版本发布需要；没有也能做原型）

验证设计数据库：

```bash
python .claude/skills/ui-ux-pro-max/scripts/search.py "admin dashboard" --design-system
```

## 确认技能已加载

在 Claude Code 里输入 `/` 应能看到四个技能名；或直接说「调用 prototype-design-interview」。
如果看不到，检查 `.claude/skills/<name>/SKILL.md` 是否存在。

## 怎么开始

### 说不清要做什么

> 我想做个原型但没想清楚：我们组每周手工排资源占用表，十几个人好几个项目，改一个人要
> 群里挨个问。你引导我问，想清楚后给我一套提示词。

自动触发 `prototype-design-interview`，产出两份文件后交接给 `prototype-workflow`。

### 需求清楚

> 新建一个原型「备件领用」：列表字段 料号/名称/规格/库存/领用人/日期/状态，
> 支持搜索和状态筛选，纯 HTML/CSS/JS。

### 改已有原型

> 给「备件领用」加一个状态筛选下拉框。

必须看到：读架构文档并复述 → 追加需求记录 → 编码 → 更新架构文档。

### 发版本

> 发布 v1.1

执行 `git add/commit/tag`，并提示 push 命令。

## 验收

```bash
ls prototypes/备件领用/
start prototypes/备件领用/index.html
```

六件套齐全、双击可开、控制台无报错即达标。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 技能没触发 | 不在包目录启动 | 在含 `.claude/skills` 的目录启动 |
| 改了代码没更新架构文档 | 流程被跳过 | 明确说「按 CLAUDE.md 六步走」 |
| Git 推送失败 | 远程未配置 | 按 `prototypes/CLAUDE.md` 配置 origin |
| 设计检索报错 | Python 缺失 | 跳过检索，直接读 SKILL.md |

## 与插件版的区别

`ui-ux-pro-max` 若你已通过插件市场安装，会同时存在两份（插件版名为
`ui-ux-pro-max:ui-ux-pro-max`）。两者规则正文一致，用哪个都行；不需要时删掉本包内的副本即可。
