# 测试说明

目的：验证迁移到 Codex / 豆包后，两个 skill 的核心行为是否还在。不是测代码质量，
是测**流程纪律**——是否先问现状、是否给具体选项、是否划边界、是否按规格产出。

原始评测集见 `evals.json`（针对 Claude skill 机器评测）。下面是人工执行版，任何 agent 都能跑。

---

## 准备

- 每个场景用**全新会话**，不要在上一个场景的上下文里接着测
- 准备一个空工作区（如 `test-proto/`），里面放 `prototypes/`（由 `工作区模板/` 复制）
- 旁听者只观察，不提示答案；用户扮演者按脚本回答
- 全程记录对话转录（复制粘贴到文件即可）

---

## 场景 1：空白头脑 + 有现状材料（必测）

**角色脚本**：你有需求，但说不清界面；能说出当前怎么手工做。

**首条输入**：

> 我想做个原型但完全没想清楚。我们组现在每周要手工排一个资源占用表，十几个人，同时好几个
> 项目，每次改一个人就得挨个群里问一遍，烦死了。想做个小工具但真不知道从哪下手，你能问我
> 几个问题帮我想清楚吗？想清楚之后给我一套提示词，我自己去建原型。

**后续回答要点**（被问到时给）：
- 现状载体：一个 Excel，表头大约是 姓名 / 项目 / 占用比例 / 开始日期 / 结束日期
- 痛点：改一个人要挨个群问，容易排冲突
- 使用者：自己和组里 2 个排期的人
- 布局偏好：看到矩阵草图后选「人 × 时间」那种
- 对「哪些不做」：这次不做审批流，不做权限

**预期行为**：

1. 第一反应不是问「你想要什么功能」，而是问「现在这张表长什么样 / 怎么排的」
2. 后续提问复用你给过的具体名词（Excel、表头、微信群、项目）
3. 布局题给出 2 个以上具象方案（选项或草图），不是开放问句
4. 问到「哪些这次不做」
5. 至少一次回声确认（复述理解、请你纠正）
6. 产出 `DESIGN_SPEC.md`：五节（意图/结构/细节/模拟数据/待确认）都有实质内容
7. 产出 `PROMPT.md`：含具体字段名或枚举值，不含「参考设计规格」类指代
8. **没有**创建原型目录或代码文件（访谈阶段不写代码）

**失败信号**：直接给方案不问现状；连问开放题；没有「不做」项；PROMPT 依赖 DESIGN_SPEC。

## 场景 2：模糊想法 → 开发流程（必测，测第二部分）

**首条输入**：

> 帮我设计个工具，管理我们部门的备件领用。我脑子里有个大概但说不出来长什么样，你引导着问我吧。
> 定下来之后给我一套提示词我去建原型。

**后续回答要点**：
- 现状：领用时在群里喊一声，有人手工记在一个共享表格里
- 痛点：不知道库存还剩多少，月底核对麻烦
- 使用者：部门 20 多人，自己和库管
- 布局偏好：列表管理型
- 主区字段：料号 / 名称 / 规格 / 库存 / 领用人 / 领用日期 / 状态
- 这次不做：审批流、库存预警

**预期行为**：
1. 完成访谈，产出两份文件
2. 接到「按这套提示词建原型」后，进入开发流程：
   - 复制模板并初始化，而不是从零手写
   - 先给布局与数据结构，等确认再编码
   - 产出可在浏览器直接打开的 `index.html` / `style.css` / `script.js`
   - 产出 `CODE_ARCHITECTURE.md`，内容与代码一致
   - `REQUIREMENTS.md` 有需求记录

**追加第三轮（修改验证）**：在原型建好后说

> 给列表加一个按状态筛选的下拉框。

**预期行为**：
1. 先读 `CODE_ARCHITECTURE.md`，并一句话复述当前架构
2. 读 `REQUIREMENTS.md`
3. 先在 `REQUIREMENTS.md` 追加变更记录，再改代码
4. 改完后更新 `CODE_ARCHITECTURE.md`（函数/事件/HTML 骨架对应项）
5. 若声明已提交，必须真有 commit+tag；无 shell 时输出命令清单

**失败信号**：跳过架构文档直接改；先改代码后补记录；改动后架构文档没同步。

## 场景 3：用户全程「不知道」（必测，测兜底）

**首条输入**：

> 我想做个原型，但脑子完全空白，一点概念都没有。你问我答吧，我尽量答。

**后续回答**：前 2–3 个问题都答「不知道」「没想过」「你定吧」。之后开始配合。

**预期行为**：
1. 第一次「不知道」后，给出具体默认值或骨架选项 + 一句理由，**不重复同一问题**
2. 出现「常见工具形态 / 骨架」供挑选的动作（台账、看板、表单等）
3. 不出现连续两轮无选项的裸开放题
4. 最终仍产出 `DESIGN_SPEC.md`，未定项记入「待确认项 / 已用默认值」
5. 产出 `PROMPT.md`，可独立成立

**失败信号**：反复追问同一题；因用户答不出而中断；产出空节或「待补充」。

## 执行方式

| 目标 agent | 怎么跑 |
|---|---|
| Codex | 仓库根放 `AGENTS.md`，`prototypes/` 用工作区模板，用其 CLI/IDE 会话执行；转录在终端 |
| 豆包 | 上传知识库 + 粘贴短提示词；每个场景新建一个对话 |
| 其他聊天 agent | 粘贴 `单文件完整版.md` 作为系统提示，再发首条输入 |
| Claude Code（对照） | 装回 `claude-skills/`，跑同一脚本，作为基线 |

每个场景重复 2 次（同一 agent）。两次差异大的项，在评分卡备注「不稳定」。
